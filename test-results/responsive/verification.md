# 响应式与交互验收 · 2026-10-20

沿用已审阅设计与现有Radix组件，未另起视觉方案。当前结果是指定环境下的本地验证，不是所有设备兼容性或生产可用证明。

## 实际修复

- 320px窄屏展开验证码说明后，原弹窗超出视口；现按可视高度限制并内部滚动。确认操作能通过滚动/键盘抵达。
- 长文本、日期输入、表单、代扣选项、账单行、办理步骤和弹窗按钮重排；短屏、横屏和安全区域留白单独处理。
- 手机/桌面“首页”导航统一，办理期间阻止导航与连点造成的任务错位。增加跳过导航入口与局部状态播报。
- 连接失败可重试；45秒超时、非JSON网关错误、连接中断保留“不确定结果”语义。禁止自动重试写入，仅回读状态。
- 旧版本冲突刷新服务器最新草稿；付款成功后不再提供准备入口；修改详情时不沿用旧余额试算。
- 协议查询过期有明确提示并禁用处置。多项撤销仅完成一项时保留REVIEW，不把整项任务伪装成完成。
- 单选意愿即时反馈，保存失败回滚。实际付款仍严格等待后端准备、明确批准和银行回执。
- 首次载入先完成任务恢复再开放操作，避免恢复中的旧任务覆盖用户新操作；受限浏览器存储下仍可通过记录恢复。

## 检查结果

`matrix.json`：14种视口，11类页面/弹窗，共154/154通过。包括320/360/390/430手机、600/640重排、768/820平板、1024/1280/1440/1920桌面，以及667×375、844×390横屏。断言全页/主要元素无横向溢出、弹窗在视口内、内容可滚动；无脚本异常。

`font-stress.json`：320/768/1440三种宽度，首页/代扣/强验证三种页面，强制150%/200%已计算字号，18/18通过。它是字号压力测试，不是浏览器工具栏原生缩放；640px重排也不是已实测200%工具栏缩放。

`recovery.json`：13/13通过，覆盖首次网关失败、显式重连、Tab焦点约束、Escape关闭、首页导航、旧版本刷新、付款已执行但HTTP回应丢失、刷新不重付、准备已受理但响应丢失。故障仅注入HTTP响应，银行沙箱操作真实落账，验证只有一笔700元扣款。

`tests/frontend-api.test.mjs`：5项Node原生测试通过，检查CSRF/同源、写入不重试、非JSON、版本错误、超时提示。

后端135项回归通过，其中新增部分完成和授权过期两项；冻结规则挑战仍正常11/12、攻击8/8、故障4/4，保留未理解倒装口语的失败，不宣称纯规则全能。

最终8770真实模型手机路径：协议查询planner=llm，连续选A/B不再需要，第一项撤销显示还剩一项；两次分别明确确认后DONE，成功操作恰为2。见`final-live-360.png`。
